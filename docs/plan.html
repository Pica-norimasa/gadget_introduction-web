01

核心的価値

既存の作品公開サービスは、暗黙のうちに「作者はすでに技術力と完成品を持っている」ことを前提にしている。 AIによって創作のハードルが崩れた今、崩れていないのは発表と発見のハードルのほうだ。 このプラットフォームの核心的価値は、「誰もが作れる時代」に対応する「誰もが発表し、誰もが発見される」仕組みを提供すること。

もう一段深く言えば、プロダクトの完成度を売る場ではなく、創作サイクル（思いつく→作る→公開する→発見される→フィードバックを受ける→改善する）そのものを毎日回したくなる場を作ることが価値の中心になる。 作品一覧ではなく、作り手の成長ログの集合体を目指す。

02

Product Huntなど既存サービスとの決定的な違い

観点Product Hunt本プラットフォーム
時間軸ローンチ日1日勝負、翌日には埋もれる常時再浮上のチャンス（急上昇率で評価）
作品の前提基本的に完成品アイデア・プロトタイプも正式な投稿形態
評価軸プロダクトの完成度・実用性発想の面白さ・パーソナリティも同等に評価
作者との関係ワンショットのローンチ告知継続的な「制作ログ」による関係構築
参加障壁英語圏・スタートアップ文化が前提非エンジニア・日本語話者を最初から想定

最も決定的なのは、PHが「その日に勝負が決まる」構造なのに対し、本プラットフォームはいつ投稿しても、いつでも発見されうる構造を持つこと。これがTikTok的な発見体験の土台になる。

03

想定ユーザー

作者になりうる層
  • AIで初めて何かを作った非エンジニア（会社員、学生、主婦・主夫など）
  • 個人開発者・ノーコーダー、副業クリエイター
  • プロエンジニアが息抜きに作る実験作・週末プロジェクト
  • 学生・ハッカソン参加者
閲覧者になりうる層
  • ガジェット好き・アーリーアダプター（発見自体を楽しむ層）
  • 他の作り手（相互に閲覧者兼作者になる、コミュニティの中核）
  • 採用担当・投資家・スカウト（才能発掘目的）
  • 単純に「便利ツールを探している」実利目的の一般ユーザー

設計上重要なのは、閲覧者の相当数が「まだ作者になっていないだけの予備軍」であるという前提。ROM専からの転換率を上げる導線が事業の成長エンジンになる。

04

作者側の利用体験

オンボーディングでは、使用しているAIツール（Claude / ChatGPT / Gemini / Cursor / Bolt / v0 など）をタグとして選ぶプロフィール設定から始める。 最初の投稿は「アイデアメモ」レベルの最小労力から始められ、あとから育てていくUXにする——生成AIのプロダクト自体が「下書きから育つ」体験を提供しているのと同じ発想。

作者ダッシュボードでは、各作品のview数・リアクション内訳・コメント・フォロワー転換率などのアナリティクスを提供。 「制作ログ」はTwitterのスレッド感覚で気軽に進捗を追記でき、通知は「誰かが試した」「フォークしたいと言っている」など創作意欲を刺激する形にする。

05

閲覧者側の利用体験

メインフィードはTikTok的な「次々に発見する」設計とし、無限スクロール・カテゴリフィルタに加え、 「今すごい勢いで伸びている無名作品」という専用セクションを常設する。 気になった作品はコレクション（保存リスト）に入れられ、そのリスト自体も公開・共有できるようにする。

「見るだけ」で終わらせないために、作品ページから実際に試せる導線（埋め込みプレビュー、ワンクリックのデモリンク）を必須に近い形で促し、 「試した感想を一言残す」文化をリアクションの一種として組み込む。

06

作品投稿フロー

  1. 作品タイプ選択 — Webアプリ / スマホアプリ / PCアプリ / ゲーム / AIツール / AI Agent / 拡張機能 / その他
  2. ステージ選択 — アイデア / プロトタイプ / ベータ / 正式リリース / 開発終了
  3. 基本情報 — タイトル、一言キャッチ、詳細説明、使用AI・ツールのタグ
  4. メディア — スクリーンショット、動画・GIF、ライブデモURL、リポジトリURL
  5. カテゴリ・タグ — 説明文からAIが自動サジェスト、作者が取捨選択
  6. 公開設定 — 全体公開 / フォロワー限定 / リンク限定（先行フィードバック募集用）

公開後、その投稿は自動的に「制作ログ」の第一エントリになる。投稿を終着点ではなく継続する記録の起点として扱うのがポイント。

08

Discovery（作品発見）の仕組み

  • パーソナライズドフィード — 閲覧・リアクション履歴に基づくレコメンド
  • 今日の掘り出し物 — 人力キュレーション＋アルゴリズムの混成枠。無名作品に意図的にスポットを当てる
  • サイコロ機能 — ランダム表示によるセレンディピティ設計
  • AI自然言語検索 — 「〜みたいなツールない？」で検索できる
  • 発想マッチング — 似たことを考えていた作者・作品同士を結びつける

核心は、フォロー数やランキング上位に依存しない「知らないものに出会う」経路を複数用意すること。これがTikTok的な中毒性の源泉になる。

09

ランキングシステム

時間窓は「今日・今週・今月・殿堂入り」を用意しつつ、PH的な「一発勝負」を避けるため、 投稿からの経過日数に関わらず急上昇率（勢い）を主指標にする。

無名の逆転枠

フォロワー数が少ない作者の作品でも、一定のエンゲージメント率（閲覧に対する反応率）を超えると、自動的にブースト枠に入る仕組みを用意する。母数の小さいアカウントから火がつくTikTok的な逆転現象を、意図的にアルゴリズムへ組み込む。

ランキングは単一の総合順位ではなく、「アイデア賞」「便利ツール賞」「初心者作品賞（非エンジニア限定）」などジャンル別に分散させ、勝ち筋を複数用意する。

10

Like・Vote・コメント・FollowなどのSNS機能

Like（ワンタップ） 複数リアクション（面白い/便利/発想◎/使ってみたい） Vote（週間投票） コメント（種別タグ付き） Follow（作者単位） Watch（作品の更新通知） Collection（公開可能な保存リスト）

単一の「いいね」だけでなく、技術評価に偏らない複数軸のリアクション（面白い／便利／発想がすごい／使ってみたい）を用意することで、 「技術力の高さだけを評価しない」という思想をUIレベルで具現化する。

11

AIを利用した作品分類・推薦機能

  • 説明文からAIがカテゴリ・技術・対象ユーザーを自動タグ付け
  • 類似作品のクラスタリングによる「これが好きなら」の提示
  • スパム・低品質投稿の一次フィルタリング
  • 作者が自己申告する「使用AIツール」情報と組み合わせた推薦精度の向上

MVPでは説明文ベースの自動タグ付けと単純な類似度推薦に留め、行動ログを用いた高度なレコメンドは後続フェーズに回すのが現実的（詳細は批判的評価で後述）。

12

Prototype・アイデア段階の作品の扱い

「アイデアのみ」を正式な投稿タイプとして用意し、実装がなくても投稿できるようにする。 アイデア投稿には「共同開発者募集」「一緒に作りませんか」のCTAを標準搭載し、実際に作品化された際は「このアイデアから生まれた」と系譜をリンクして残す。

ステージバッジ（アイデア／プロトタイプ／ベータ／公開中）で期待値を事前に調整し、「未完成だから低評価」という空気を構造的に防ぐ。ただし、これは閲覧体験とのトレードオフでもある（後述の批判的評価を参照）。

13

「制作過程」をコンテンツとして扱う方法

ビルドログ機能により、短文＋画像で進捗を都度追加できるようにする（個人開発の実況・開発日誌の感覚）。 各ログ単体にもいいね・コメントが可能で、ログが積み上がること自体が「本気で作っている人だ」という信頼のシグナルになる。

長期的には、人気作者の制作過程そのものがメイキング動画のように消費されるコンテンツへと育つ。作品よりも先に「その人の作り方」のファンがつく状態が理想形。

14

バージョンアップ履歴の仕組み

GitHub Releases的な構造化されたバージョン履歴（v0.1 → v1.0）を用意し、各バージョンに変更点とスクリーンショット差分を紐付ける。 重要なのは、ユーザーからの要望コメントと実装状況をトレーサビリティのある形で接続すること——「この機能ほしい」というコメントが、後のバージョンで「実装しました」に変わる体験は、作者と閲覧者の関係を強くする。

15

作者とユーザーのコミュニケーション方法

  • 公開コメント欄（スレッド形式、作者による返信ピン留め）
  • 構造化フィードバックフォーム（バグ報告／機能要望／感想を分離し、作者がステータス管理できるミニIssueトラッカー）
  • 作品ごとのQ&Aセクション
  • 将来的なDM機能（招待制コミュニティ内での深い交流）
16

バイラルする仕組み

  • シェアするだけで映える自動生成OGP作品カード
  • ブログ・Xに貼れる埋め込みウィジェット
  • 週刊ハイライトのニュースレター／SNS投稿による外部露出
  • バッジ獲得・ランクイン通知をシェアしたくなるデザイン
  • Remix機能 — 他人の作品にインスパイアされた派生作品を作れる仕組み。系譜がツリーとして可視化され、それ自体が話題化しやすい
17

初期ユーザーを獲得する方法

  1. 「AIでアプリ作った」系のXコミュニティにいる層を直接シードユーザーとして勧誘する
  2. 著名な個人開発者・インフルエンサーに先行投稿してもらい、ローンチ時の話題を作る
  3. 既にX等で発表済みの作品をワンクリックで移植できるインポート導線を用意する
  4. ハッカソン・コンテストとのタイアップで作品の初期供給源を確保する
  5. 「今週のベストアイデア」を運営自身が積極的にメディア・SNSで紹介し外部流入を作る
18

マネタイズ方法

  • フリーミアム — Pro会員（詳細アナリティクス、優先掲載枠、カスタムドメイン）
  • スポンサーシップ — 「Claude公式サポーター枠」のようなAIツール企業とのバッジ連携
  • 求人・スカウト機能 — 企業が才能を発掘し採用オファーを出す成功報酬制ジョブボード
  • 投げ銭 — 作者への直接支援＋手数料
  • 将来的なマーケットプレイス — テンプレート・有料版作品の仲介手数料

Discoveryのメイン面に有料掲載を出すことは避ける。Product Huntの反面教師として、発見体験の公平性が信頼の根幹であることを明確にする。

20

サービス名候補

Kizashi 兆し

「芽生えの兆し」という創作サイクルの初期段階そのものを表す和語。英語圏にも発音しやすく、ドメインの独自性も高い。

MakeLoop

「作る→見つかる→改善する」という循環構造を英語圏にもそのまま伝えられる直接的なネーミング。

Hirameki 閃き

アイデアそのものへの価値づけを最も直接的に表現する語。技術力ではなく発想を評価する思想と一致する。

Tsukurun つくるん

親しみやすい語感で非エンジニア層への心理的ハードルを下げるネーミング。カジュアルな印象が強み。

Sparkbase

アイデアの火種（spark）が集まる場所という比喩。スタートアップ的な語感で投資家・企業連携にも馴染みやすい。

Nobiru 伸びる

作品と作者の「伸びしろ」を主役にするコンセプトを直接表す。未完成歓迎の思想と相性が良い。

Part 2 — 総合企画

コンセプトの統合

個別項目の設計を踏まえ、事業全体としての骨格・優先順位・技術構成・画面設計・競合比較・そして最大の課題までを一つに束ねる。

サービス全体のコンセプト

「アイデアを、育てながら見せる場所」。完成品の展示場ではなく、未完成のまま公開し、反応を受けながら育てていく過程そのものを主役にする創作プラットフォーム。

最重要機能

  1. 常時発見フィード＋無名逆転ブースト（TikTok的な発見体験の中核）
  2. ビルドログ（制作過程を継続的に発信する機能）
  3. ステージ別投稿（アイデア段階からの投稿を正式に許可）
  4. 複数軸リアクション（技術力だけでなく発想を評価する仕組み）

差別化ポイント／日々の訪問理由／投稿を続ける理由

差別化ポイント

未完成歓迎の投稿思想、常時発見アルゴリズム、無名逆転ブースト、ビルドログ文化、AI利用の可視化バッジ——単体ではなく、これらが組み合わさって初めて「アイデア一発勝負ではない」プラットフォームになる。

ユーザーが毎日訪れる理由

発見フィードが毎日変わる中毒性、フォロー中の作者のビルドログ更新が気になる感覚、自分の投稿への反応通知。

作者が投稿し続ける理由

アナリティクスで成長が可視化される、ビルドログで日々応援される感覚、フォロワーとの直接対話、実績バッジ、将来の採用・投資機会につながる期待。

このサービスが成功するための最大の課題

鶏と卵問題——閲覧者がいなければ作者は投稿を続けず、面白い作品がなければ閲覧者は定着しない——が最大の壁になる。 加えて、「誰でも作れる」ことの裏返しとして、似たようなAI生成物が大量発生し、Discoveryの質が急速に劣化するリスクを抱えている。

批判的評価

本当にユーザーは集まるのか——厳しく評価する

懸念 1 — ターゲットの母数を過大評価している

「非エンジニアでもAIでアプリが作れる時代」は事実だが、実際にBolt・v0・Replit・Claudeなどを使いこなして「公開に値する何か」を作り切れる非エンジニアは、2026年時点でもまだ少数派のアーリーアダプター層に限られる。 企画全体が前提とする「作者予備軍の巨大な母数」は、想定より一桁小さい可能性が高い。

懸念 2 — 「未完成歓迎」は閲覧体験を静かに壊す

未完成品だらけのプラットフォームは、「試してみたら動かなかった」の連続で閲覧者を消耗させる。 Product Huntが完成品前提なのは、閲覧者の時間を尊重するための合理的な設計であり、これを崩すと発見体験そのものの質が下がる。 「技術力でなくアイデアを評価する」という思想と「ちゃんと動くものを試したい」という閲覧者ニーズは、放置すると正面から衝突する。

懸念 3 — AI生成物の同質化リスク

誰でも簡単に作れるようになった結果、似たようなTodoアプリ、似たようなチャットボットが大量生産され、Discoveryの質が急速に劣化する現象は、AI生成コンテンツを扱う他プラットフォームで既に観測されている。 「アイデアの面白さ」を測る仕組みが弱いままだと、差別化ポイントそのものが埋没する。

懸念 4 — 収益化までの距離が長すぎる

フリーミアム・スポンサー・求人手数料はいずれも「十分な規模のユーザーベース」を前提とする収益源であり、初期は事実上ゼロ収益が続く。 個人開発規模のPMFに数年かかる可能性があり、相応の資金体力が必要になる。

懸念 5 — TikTok的レコメンドはMVPで作れない

行動ログ基盤・ベクトル検索・A/Bテスト基盤を要する高度なレコメンドは開発コストが非常に高く、初期に本格実装するのは非現実的。 しかし簡易ロジックで妥協すると、「発見の楽しさ」という核心価値そのものが弱くなるジレンマを抱える。

修正提案
  1. 完全公開ではなく初期は招待制・審査制にする。規模より先に、濃く質の高い最初の100作品を作る。
  2. 「未完成OK」と「動くもの」をゾーニングで分離する。メインDiscoveryフィードは動作確認済みの作品のみとし、アイデア投稿は "Lab" のような別セクションに隔離して期待値の衝突を防ぐ。
  3. 評価軸は最初から1つに絞る。複数軸リアクションや多ジャンルランキングは魅力的だが、初期は「急上昇スコア」単軸に留め、複雑化は後回しにする。
  4. レコメンドは背伸びしない。MVPは人力キュレーション＋単純な急上昇アルゴリズムに徹し、「今日の掘り出し物」を運営が手動で選ぶ体制から始める。
  5. 最初から広く狙わず、単一ニッチに絞る。例えば「日本語圏の個人開発者コミュニティ」など特定クラスタに集中し、そこで濃い文化を作ってから拡張する。
  6. 運営自身がシードコンテンツを用意する。既存の個人開発者に声をかけ、ローンチ前に50〜100件の作品を先行投稿してもらい、「空っぽの棚」状態を回避する。

結論として、コンセプトの思想（未完成歓迎・発想重視・常時発見）自体は既存サービスの構造的な穴を正しく突いている。 ただし「規模」「網羅性」「高度なアルゴリズム」を初期から狙うと、鶏卵問題と品質崩壊の両方に同時に殴られる。 最初の一歩は、狭いニッチで「ここでしか得られない発見体験」を作り切ることに尽きる。
